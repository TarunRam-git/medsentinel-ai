# HTTP API

All endpoints are served by Next.js. Browser mutations require a session cookie, JSON Content-Type, and an Origin matching APP_ORIGIN. Responses never contain session or integration secrets. Ingestion uses a bearer key instead of session cookies.

| Method | Endpoint              | Authorization                       | Purpose                           |
| ------ | --------------------- | ----------------------------------- | --------------------------------- |
| GET    | /api/health           | Public                              | Process liveness                  |
| GET    | /api/auth/session     | Optional session                    | Current user                      |
| POST   | /api/auth/login       | Origin + credentials                | Start session                     |
| POST   | /api/auth/demo        | Origin; ENABLE_DEMO=true            | Synthetic role session            |
| POST   | /api/auth/logout      | Session + Origin                    | Revoke session                    |
| GET    | /api/snapshot         | Session                             | Role-filtered workspace           |
| POST   | /api/registry         | Administrator                       | Register patient/device           |
| POST   | /api/ingest           | INGEST_API_KEY bearer               | Normalize and correlate one event |
| POST   | /api/fhir             | INGEST_API_KEY bearer               | FHIR R4 Observation subset        |
| POST   | /api/scenarios        | Admin/researcher + demo             | Generate synthetic events         |
| POST   | /api/alerts/:id/state | Admin/clinician/security/biomedical | Record human review               |
| GET    | /api/export           | Admin/security/researcher           | Download minimized SIEM JSON      |

## Normalized event

```json
{
  "id": "connector-event-001",
  "source": "device",
  "patientId": "PT-1024",
  "deviceId": "PMP-001",
  "timestamp": "2026-09-07T10:00:00Z",
  "kind": "infusion telemetry",
  "values": { "deviceRate": 5, "signalQuality": 0.98 },
  "provenance": "registered-connector:v1"
}
```

Sources: device, vitals, ehr, security, workflow. IDs are at most 120 safe characters. The timestamp must be RFC3339 with a zone, no more than 60 seconds ahead of server time. Events outside a common five-minute window are not correlated. The same event ID is idempotent. The event must reference an existing patient/device association. `receivedAt` is generated by the server, not accepted from the client.

Feature values: orderRate/deviceRate (same operator-defined unit), spo2/independentSpo2 (percentage), authFailures (count), packetLoss (percentage), latency (milliseconds), deviceError/configChange/signalQuality (0–1). The engine normalizes eight features into [0,1]. Missing values receive documented neutral defaults; source coverage and signal quality are reported separately. This is not a complete missing-data or waveform processing pipeline.

## Review state machine

```text
open → acknowledged → investigating → resolved | false_positive
                    └──────────────→ resolved | false_positive
```

Send status, a note of 5–2,000 characters, and expectedUpdatedAt from the inspected record. Concurrent changes return 409. Final states do not reopen automatically; new evidence can create a new alert. Acknowledgement or resolution records a human decision only.

## FHIR subset

Accepts final/amended/corrected Observation resources with subject.reference=Patient/:id and device.reference=Device/:id. Supports LOINC 59408-5 with UCUM `%` and LOINC 8867-4 with UCUM `/min`. Effective timestamps and required coding systems are validated. It is an ingestion adapter, not a full FHIR server.

## Registry

POST `{ "type": "patient", "record": Patient }` or `{ "type": "device", "record": Device }`. See src/lib/registry.ts for exact schemas. The dashboard provides administrator forms. IDs cannot be overwritten, and device patient/ward associations must match. New dashboard devices start offline until telemetry arrives. Account provisioning is a local operator command: npm run user:create.

## Errors

400 invalid data; 401 absent/invalid identity; 403 role/origin restriction; 404 missing resource; 409 duplicate registry ID, stale review, or illegal transition; 413 body too large; 415 unsupported media type; 422 invalid identity association or FHIR semantics; 429 rate limit. Unexpected server errors return generic messages without sensitive details.
